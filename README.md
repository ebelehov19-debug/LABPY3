# Лабораторная работа №3: Очередь задач (итераторы и генераторы)

## Цель работы
Освоить реализацию пользовательских коллекций, протоколов итерации и ленивых вычислений на примере очереди задач. Научиться создавать итераторы с явным управлением состоянием, применять генераторы для потоковой обработки данных и проектировать API коллекций, совместимых со стандартными конструкциями Python. 

## Постановка задачи
Необходимо разработать очередь задач (TaskQueue), поддерживающую итерацию, фильтрацию и потоковую обработку задач. Очередь должна обеспечивать возможность многократного обхода, ленивую фильтрацию без создания копий данных и корректную работу с большими объёмами задач.

**TaskQueue** - пользовательская коллекция, содержащая:
-  `add(task)` - добавление одной задачи
- `add_all(tasks)` - добавление нескольких задач
- `__len__` - количество задач в очереди
- `__contains__` - проверка наличия задачи
- `__iter__` - возвращает новый итератор
- `iter_filtered(status, priority, predicate)` - ленивая фильтрация
- `pending_tasks()`-  фильтр по статусу pending 
- `in_progress_tasks()` -  фильтр по статусу in_progress
- `completed_tasks()` - вычисляемое свойство готовности к выполнению
- `high_priority_tasks()` - фильтр по приоритету high
- `critical_priority_tasks()` -  фильтр по приоритету critical
- `ready_to_execute()` -  фильтр по готовности к выполнению
- `first(predicate)` - первая подходящая задача

## Итераторы

### Внутренний итератор `_TaskIterator `
- Реализует протокол итератора (`__iter__` возвращает `self`,` __next__` возвращает следующий элемент)
- Хранит ссылку на список задач и текущий индекс 
- При достижении конца списка явно выдает StopIteration

### PriorityField — валидация приоритета
- Допустимые значения: `low`, `medium`, `high`, `critical`
- Не зависит от регистра приоретета 
- Используется для priority

## Генераторы

### iter_filtered - ленивая фильтрация
- Функция-генератор, использующая `yield` для отдачи подходящих задач
- Не создаёт копию списка задач
- Фильтрация выполняется на лету при итерации

### Дополнительные методы-обертки 
- `pending_tasks()` - возвращает `iter_filtered(status="pending")`
- `high_priority_tasks()` - возвращает `iter_filtered(priority="high")`
- `ready_to_execute()` -возвращает `iter_filtered(predicate=lambda t: t.is_ready_to_execute)`

## Исключения 
- StopIteration-стандартное исключение для завершения итерации (явно вызывается в `__next__`)

## Обоснование выбора хранения
Хранение задач в list[Task] необходимо для выполнения требований ТЗ и не является избыточным хранением данных, потому что все остальные объекты будут реализовываться через генераторы. И хранение не списком будет вызывать большие трудности для реализации ТЗ.

## Примеры использования программы
1. Интерактивная проверка 
``` 
python -c "
from src.contracts.task import Task
from src.inbox.task_queue import TaskQueue
queue = TaskQueue()
task1 = Task(id="1", payload="Отправить отчёт", priority="high")
task2 = Task(id="2", payload="Проверить код", priority="medium")
task3 = Task(id="3", payload="Задеплоить приложение", priority="high")
queue.add(task1)
queue.add_all([task2, task3])
for task in queue:
    print(task.id, task.payload)
for task in queue:
    print(f"Ещё раз: {task.id}")
for task in queue.pending_tasks():
    print(f"Pending: {task.id}")
for task in queue.high_priority_tasks():
    print(f"High priority: {task.id}")
for task in queue.ready_to_execute():
    process(task)
tasks_list = list(queue)
print(tasks_list)
total = sum(1 for _ in queue)
print(total)
print(f"Всего задач: {len(queue)}")
"
```
